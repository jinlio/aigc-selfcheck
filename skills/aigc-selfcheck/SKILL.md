# aigc-selfcheck：提交前的 AIGC 风险自查

把一篇中文论文/长文拆成句子和滑动窗口，用本地检测器给出风险分，再把分数翻译成普通作者能看懂的原因、原文证据、修改建议和“这段先别改”的提示。目标是去掉 AI 辅助写作留下的模板化痕迹，同时不改变文章结构、事实、数据、引用。它**不是**知网、朱雀等官方检测器，也不能预测它们的判定。

## 什么时候用

- 用户用了 AI 辅助写作，要在提交论文、课程作业、期刊稿件前做一次自查。
- 用户问“为什么这段被标成 AI”“哪里最像 AI”“先改哪一段”“怎么改得更像人写的”。
- 用户改完一版，想知道“分数有没有降、哪一章变好了”。
- 用户想保留论文结构和实验细节，只想要具体、可解释的修改线索，而不是“一键洗稿”。

## 什么时候不要用

- 用户要求“保证通过知网/朱雀检测”或“把 AI 率降到 0”。直接说明本工具做不到，也不承诺。
- 用户要求自动重写全文、批量洗稿、规避检测。只提供建议和受约束的改写示例，不代替作者改写，不自动替换原文。
- 文本是文学创作、财经法律评论、新闻报道等校准集之外的语域。可以跑，但必须说明“未经校准，结果仅供参考”。
- 用户给的是 URL、网盘链接或需要登录的在线文档。只接受本地文件。

## 前置条件

在项目根目录执行一次：

```bash
uv sync
```

首次运行会下载/加载本地模型权重，可能需要几分钟；文本不会离开本机。按机器配置选档位：

- `--profile lite`：纯 CPU、0.5B、只用规则建议，适合低配笔记本。
- `--profile balanced`：b+c、2B、设备自动，默认推荐；有加速设备时默认开启模型改写示例。
- `--profile max`：a+b+c、2B，配置足够时使用完整三路。

纯 CPU 运行时，`balanced`/`max` 会自动跳过 2B 模型改写，只保留规则建议，避免低配机器被生成拖慢；需要强制生成时加 `--llm-advice`。

支持 `.docx`、文本型 `.pdf`、`.txt`、`.md`。扫描版 PDF 需要先 OCR；加密 PDF 需要先解除密码。

## 工作流

### 1. 先跑一次自检

```bash
python skills/aigc-selfcheck/scripts/check.py 论文.docx --profile balanced --out selfcheck-report.html
```

需要机器可读结果时加 `--json`。报告是单文件 HTML，直接双击打开，不需要联网。低配机器用 `--profile lite`；只想用规则建议时加 `--no-llm-advice`，强制开启模型建议时加 `--llm-advice`。

### 2. 用户问“为什么”时，输出白话解释

```bash
python skills/aigc-selfcheck/scripts/explain.py 论文.docx --top 8
```

摘要会给出：综合分与区间带、证据是否充足、章节风险排序、最需要看的句子、每句的白话原因、原文证据和修改建议，以及“公式/符号密集”“方法/结果/结论段易误伤”“三路分歧大”“文本偏短”等先别改提示。句级理由只引用这一句里真实出现的词句；如果风险来自整段统计特征，会明确写“风险来自所在段落”。

### 3. 用户问“先改哪里”时，输出修改计划

```bash
python skills/aigc-selfcheck/scripts/plan.py 论文.docx
```

计划按“单独处理这一段后全文综合分会下降多少”排序。它是敏感性估计，不是分数承诺。优先改有实质问题的段落；不要为了降分删实验细节、堆口语词或故意写病句。若报告里有“所在段落改写示例”，把它当参考，不要直接替换原文。

### 4. 用户改完一版后，做前后对比

```bash
python skills/aigc-selfcheck/scripts/compare.py 新版本.docx --old 旧版本.docx --out compare.html
```

输出综合分变化、区间带变化和章节级变化。章节按标题匹配；标题改动会被视为新增/删除。

### 5. 直接调用 CLI（可选）

```bash
uv run aigc-selfcheck 论文.docx --profile balanced
uv run aigc-selfcheck 论文.docx --profile lite
uv run aigc-selfcheck 论文.docx --json
uv run aigc-selfcheck 论文.docx --llm-advice
uv run aigc-selfcheck 论文.docx --no-llm-advice
uv run aigc-selfcheck 论文.docx --enhanced
uv run aigc-selfcheck 新版本.docx --compare-with 旧版本.docx --out compare.html
```

## 怎么读结果

- **综合风险分 0–100**：低 0–34、中 35–64、高 65–100。它由窗口 median 与 P90 映射而来，用于快速比较，不改变区间带判定。
- **区间带**：低 = median < 0.45 且 P90 < 0.60；高 = median ≥ 0.60 或 P90 ≥ 0.85；其余为中。
- **证据是否充足**：少于 3 个窗口或 300 个汉字时，分数不稳定，先不要下结论。
- **章节地图**：按标题聚合，用来定位“哪一章最需要看”，不改变全文分数。
- **修改计划**：单段敏感性排序，告诉你“先改哪一段更划算”，不是“改完一定降到多少分”。
- **先别改提示**：公式/符号密集、方法/结果/结论段、三路分歧大、文本偏短。这些地方检测器容易误伤，先人工确认，不要为了降分删改关键内容。
- **所在段落改写示例**：实验性，只对最高风险窗口生成。它必须引用原文、不新增数字或原文没有的效果承诺；校验不通过会自动回退到规则建议。只展示，不自动替换原文，使用前必须人工确认。
- **增强召回**：实验性，默认关闭；它会提高召回，也会增加人写误伤。报告里标为“实验”，只当复核线索。

## 安全与边界

- **只读本地文件**：不接受 URL；不读取环境变量里的凭据；不把文本发到任何远端服务。
- **不自动改写**：只输出原因、建议和受约束的改写示例，不调用编辑工具改用户的论文，不自动替换原文。
- **模型建议也在本地**：用已加载的 Qwen 基座生成，不调用云端 API；生成结果必须通过“与原文共享中文二元组、不新增数字”校验。
- **不承诺官方结果**：明确告诉用户“这是本地启发式估计，不是知网/朱雀的判定”，也不保证修改后平台 AI 率一定下降。
- **不调参**：不要根据用户单篇论文的分数改阈值、α、μ/σ；校准常量是冻结的。
- **不把分数当学术不端认定**：高分只说明写法容易被检测器注意到，不等于作者用了 AI。
- **保护隐私**：报告默认写在本地；不要主动把报告或原文粘贴到外部服务。

## 常见问题

- **PDF 报“没有可提取文本”**：多半是扫描件，先 OCR，或让用户提供 `.docx`。
- **PDF 报“已加密”**：先解除密码保护。
- **运行很慢**：用 `--profile lite`（纯 CPU、0.5B、规则建议），或加 `--no-llm-advice` 关闭模型改写示例。
- **模型建议没有出现**：`lite` 默认关闭；`balanced`/`max` 在纯 CPU 上会自动跳过（需要时显式加 `--llm-advice`）。生成失败或未通过校验时，报告会显示“大模型建议已跳过”并回退规则建议。
- **分数和上次不一样**：检查是否改了档位、检测路、设备、增强开关或文档结构；不要用单次波动调阈值。
- **没有章节地图**：文档没有标题结构，或内容都被结构过滤跳过；这不影响逐句热力图。
