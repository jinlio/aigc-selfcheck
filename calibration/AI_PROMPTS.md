# AI 样本生成提示词包（第三轮语料扩容）

现有 12 段 AI 样本全部由 GLM 生成，**生成器多样性是当前最大的空白**——检测器如果只见过一种
生成器的文风，换一个模型就可能完全失效。本提示词包交给人工，在另外四个平台上生成，原样落盘。

## 平台（四选其四，每条提示词每个平台各跑一次）

| 平台 | 文件名前缀 | 建议入口 |
| --- | --- | --- |
| DeepSeek | `ds-` | 网页版对话（deepseek-chat） |
| Kimi | `kimi-` | 网页版对话 |
| 豆包 | `doubao-` | 网页版对话 |
| 通义千问 | `qwen-` | 网页版对话（tongyi） |

注意：**不要用 GLM/智谱系产品生成**——现有 12 段已是 GLM，再生成不增加多样性。
使用各平台默认模型、默认设置（不调温度、不开深度思考/推理模式），像普通用户一样直接发提示词。

## 提示词（共 5 条 × 4 平台 = 20 段）

四类文体覆盖论文自检的典型场景；主题与人类语料（技术博客/学习方法）刻意重叠，
防止检测器学到「主题捷径」而不是文风差异。

1. **技术说明**：请用一段话（150~250字）介绍什么是数据库索引，说明它为什么能加快查询速度。不要分点，不要标题，写成一整段。
2. **议论**：请用一段话（150~250字）论述「开源软件对技术发展的利大于弊」这一观点，给出你的理由。不要分点，写成一整段。
3. **学术摘要**：假设你刚完成一篇关于在线学习效果的实证研究论文，请写一段150~250字的中文摘要，包含研究目的、方法、结果与结论。不要分点，写成一整段。
4. **科普**：请用一段话（150~250字）向普通读者解释深度学习是怎么「认出」图片里的猫的。语言通俗，不要分点，写成一整段。
5. **方法建议**：请用一段话（150~250字）说明大学生如何制定有效的时间管理计划并坚持执行。不要分点，写成一整段。

## 存盘规则（关键）

- 每段存一个文件，放到 `calibration/ai/`，命名：`<前缀><序号>-<主题>.txt`
  （例：`ds-01-数据库索引.txt`、`kimi-03-学术摘要.txt`）。
- 文件第一行写溯源注释，空一行后贴正文：

  ```
  <!-- 平台: DeepSeek | 模型: deepseek-chat | 日期: 2026-10-26 | 文体: 技术说明 | 提示词: 1 -->
  ```

  构建脚本会自动剥离该注释行，只把正文送进语料；模型名不确定就照网页版显示的填。
- **正文必须原样保存，一个字都不要改**——改过的就不再是「纯 AI 样本」（人工润色另有一类语料）。
- 提示词重复生成过多次的，只保存最终采用的那一段，不要把多版都存进来。
- 全部 20 段生成完，运行 `uv run python scripts/build_calibration.py` 重建校准集即可，无需改代码。

## 为什么这样设计

- **不规定文风、不要求「写得像人」**：样本必须代表普通用户的默认产出；提示词里要求
  「避免 AI 味」等于教模型规避我们自己的检测器，会污染评测。
- **一段一文、禁分点**：检测管线以自然段为窗口，列表和标题会被预处理过滤，收集无意义。
- **150~250 字**：与人类语料的段落门槛（100~400 汉字）对齐，窗口切分才可比。

0.17），单段生成器折的结论不可靠。规则同批 1：默认设置、原样入库、剥离聊天元文本
（豆包段尾「（全文 N 字）」、Qwen 追问尾巴）。

### 2. Gemini（`gemini-01-05`，人工程）

新平台，5 段，规则同上。溯源头 `平台: Gemini | 模型: 网页版默认（未记录）`。

### 3. 阿里云百炼 API 批（`ds41/ds4p/qw37/qw38` 各 5 段，`scripts/gen_ai_api.py`）

聚合端点，OpenAI 兼容协议。已用模型：deepseek-v4.1-flash-1017、deepseek-v4-pro-0813、
qwen3.7-max、qwen3.8-max（GLM 系与音视频系模型跳过——前者已覆盖，后者非文本）。

```bash
# 密钥只从环境变量读，源码/文档不落任何可用凭据字面量
export OPENAI_API_KEY=...        # 与 OPENAI_API_BASE_URL（百炼 compatible-mode 地址）
uv run python scripts/gen_ai_api.py --list-models          # 先看可用模型
uv run python scripts/gen_ai_api.py --model qwen3.8-max --prefix qw38 --start-no 1
```

约束与已知混杂，如实记录：

- 脚本内置 SSRF 防护：仅 https、host 白名单（`dashscope.aliyuncs.com` /
  `.qianwenaiapi.com`）、DNS 解析必须公网 IP、拒绝重定向、路径须含 compatible-mode。
- max_tokens=800；汉字数落在 100~450 外自动重试一次；剥离 markdown 代码围栏。
- 溯源头带模型名与 `搜索: 关闭（API 无联网搜索） | 思考: 关闭 | 参数: 服务端默认`——
  与网页批「默认开搜索」存在分布差异，评测解读时需注意（见 calibration/README v4 节）。
- 生成器分组按**模型**而非平台（聚合端点平台字段无区分度），
  见 `cv_evaluate.py: generator_of`。

## 第九轮（2026-10-26，v9：MiniMax-M2.5 API，四个新语域提示词包）

目标语域是既有语料的空白：新闻（news）、百科说明（wiki）、公文（gov）、
文学散文（literary）。人写侧同步补了 gov 语域的统计公报/政府工作报告段落；

（模型 MiniMax-M2.5，temperature=1.0 / top_p=0.95，max_tokens=3000 含思考
预算；正文只取 `type=="text"` 块，思考内容不进语料）。

每个语域包 12 个主题 × 2 个提示词模板（占位符 `{topic}`）× 6 轮重复，
共 576 任务；成功 527 段（失败 47 条重试后仍不达长度/含清单格式的自动
落盘标 fail），其中**每语域 10 段并入主语料 `calibration/ai/`**（40 段，
v9 test 的整组留出生成器），其余 487 段留在私有归档作 v10 train 候选与

散文意象四类，各配两个措辞不同的模板以防模板指纹）。

溯源头沿用统一格式（平台/模型/日期/文体/语域/提示词/轮次/搜索/参数），
